# Data Model - Intent Detection and Agent Routing

## Entity: UserRequest

Purpose: Canonical incoming request payload entering the orchestrator routing pipeline.

Fields:
- request_id: string (required, unique)
- user_id: string (required)
- session_id: string (required)
- utterance: string (required, normalized non-empty text)
- received_at: string (required, ISO-8601 timestamp)
- metadata: object (optional)

Validation rules:
- `utterance` MUST remain non-empty after trim/normalization.
- `request_id`, `user_id`, and `session_id` MUST be present before intent detection runs.

State transitions:
- `received` -> `classified` -> `routed`
- `received` -> `routed` (companion fallback when classification is inconclusive but syntactically valid)

## Entity: IntentScore

Purpose: Represents a domain confidence candidate produced by the intent classifier.

Fields:
- request_id: string (required, FK -> UserRequest.request_id)
- domain: enum (required: `calendar | travel | dining | news | companion`)
- confidence: number (required, range `0.0..1.0`)
- model_version: string (required)

Validation rules:
- One score per supported domain SHOULD be produced for a request.
- `confidence` MUST be bounded in `[0.0, 1.0]`.

Relationships:
- Many `IntentScore` rows belong to one `UserRequest`.

## Entity: RoutingPolicySnapshot

Purpose: Captures the policy values used for deterministic routing at decision time.

Fields:
- request_id: string (required, FK -> UserRequest.request_id)
- specialist_threshold: number (required)
- tie_window: number (required, default `0.03`)
- precedence_order: array[string] (required, fixed `['calendar','travel','dining','news']`)
- evaluated_at: string (required, ISO-8601 timestamp)

Validation rules:
- `tie_window` MUST equal configured policy value for this deployment.
- `precedence_order` MUST match the configured deterministic order.

## Entity: RoutingDecision

Purpose: Final single-destination routing outcome generated by orchestrator.

Fields:
- request_id: string (required, FK -> UserRequest.request_id)
- selected_domain: enum (required: `calendar | travel | dining | news | companion`)
- selected_confidence: number (required, `0.0..1.0`)
- threshold_passed: boolean (required)
- tie_detected: boolean (required)
- tie_resolved_by_precedence: boolean (required)
- fallback_to_companion: boolean (required)
- rationale: object (required)
- decided_at: string (required, ISO-8601 timestamp)

`rationale` object minimum fields:
- top_candidates: array[{domain, confidence}] (required)
- threshold_value: number (required)
- tie_window_value: number (required)
- tie_break_winner: string (optional)
- reason_code: enum (required: `highest_above_threshold | tie_break_selected | below_threshold_fallback`)

Validation rules:
- Exactly one `selected_domain` MUST be produced per valid request.
- If `selected_domain = companion`, `fallback_to_companion` MUST be true.
- `tie_resolved_by_precedence` MUST be true only when `tie_detected` is true and selected domain is specialist.

State transitions:
- `computed` -> `dispatched`
- `computed` -> `failed` (dispatch/service failure with failure event)

## Entity: RoutingDecisionRecord

Purpose: Trace/audit record stored in request processing context for observability and replay.

Fields:
- record_id: string (required, unique)
- request_id: string (required, FK -> UserRequest.request_id)
- orchestrator_handler: string (required, constant `orchestrator`)
- decision: RoutingDecision (required)
- emitted_event: string (required, pattern `<domain>.<action>.<status>`)
- created_at: string (required, ISO-8601 timestamp)

Validation rules:
- Every routed request MUST have exactly one `RoutingDecisionRecord`.
- `orchestrator_handler` MUST always be `orchestrator`.
- `emitted_event` naming MUST comply with constitution event format.

## Relationships Summary

- `UserRequest` 1 -> N `IntentScore`
- `UserRequest` 1 -> 1 `RoutingPolicySnapshot`
- `UserRequest` 1 -> 1 `RoutingDecision`
- `UserRequest` 1 -> 1 `RoutingDecisionRecord`

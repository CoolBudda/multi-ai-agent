# Data Model - Orchestrator Single Entry Point

## Entity: ClientRequest

Purpose: Canonical representation of a client-initiated assistant request entering the system.

Fields:
- request_id: string (required, unique)
- user_id: string (required)
- session_id: string (required)
- message: string (required, non-empty after trim)
- channel: string (required, enum: `web`, `mobile`, `api`)
- created_at: string (required, ISO-8601 timestamp)
- metadata: object (optional, string->scalar/object map)

Validation rules:
- message MUST be non-empty after normalization.
- request_id MUST be present before routing starts.
- Any request missing required identifiers is rejected as malformed.

State transitions:
- `received` -> `validated` -> `routed`
- `received` -> `rejected` (malformed)

## Entity: RoutingDecision

Purpose: Deterministic routing output generated by the Orchestrator for a validated client request.

Fields:
- request_id: string (required, foreign key -> ClientRequest.request_id)
- initial_handler: string (required, constant `orchestrator`)
- target_domain: string (required, enum: `calendar`, `travel`, `dining`, `news`, `companion`)
- confidence: number (required, 0.0 to 1.0)
- fallback_applied: boolean (required)
- rationale: string (optional)
- decided_at: string (required, ISO-8601 timestamp)

Validation rules:
- initial_handler MUST always equal `orchestrator`.
- target_domain MUST be a supported domain.
- confidence MUST be within [0.0, 1.0].
- fallback_applied MUST be true when target_domain is `companion` because of low/ambiguous confidence.

State transitions:
- `computed` -> `dispatched`
- `computed` -> `failed` (downstream unavailable)

## Entity: RoutingRecord

Purpose: Auditable trace record proving orchestrator-first handling and final request outcome.

Fields:
- record_id: string (required, unique)
- request_id: string (required, foreign key -> ClientRequest.request_id)
- entry_path: string (required, constant `orchestrator`)
- initial_handler: string (required, constant `orchestrator`)
- routed_to: string (required, same domain set as RoutingDecision.target_domain)
- status: string (required, enum: `succeeded`, `failed`, `rejected`)
- failure_code: string (optional, required when status = `failed`)
- rejection_code: string (optional, required when status = `rejected`)
- user_message: string (required)
- created_at: string (required, ISO-8601 timestamp)
- updated_at: string (required, ISO-8601 timestamp)

Validation rules:
- Every accepted request MUST produce exactly one RoutingRecord.
- For failed downstream execution, failure_code MUST be populated and initial_handler remains `orchestrator`.
- For direct specialist invocation attempts, status MUST be `rejected` and rejection_code set to `direct_specialist_access_denied`.

State transitions:
- `open` -> `succeeded`
- `open` -> `failed`
- `open` -> `rejected`

## Entity: DirectAccessAttempt

Purpose: Track and respond to client attempts to call specialist routes directly.

Fields:
- attempt_id: string (required, unique)
- request_id: string (required)
- attempted_target: string (required, specialist domain name)
- denied_at: string (required, ISO-8601 timestamp)
- rejection_code: string (required, constant `direct_specialist_access_denied`)
- user_message: string (required)

Validation rules:
- attempted_target MUST NOT be `orchestrator`.
- user_message MUST clearly state that only orchestrator entry is supported.

Relationships:
- DirectAccessAttempt.request_id references ClientRequest.request_id.
- DirectAccessAttempt can materialize as a RoutingRecord with `status=rejected`.
